## 2. Website Submission Guidelines

### General Requirements

* **Format:** Static site; accessible via a root `index.html` in a "zip folder" style submission.
* **Links:** All links must be relative to ensure self-contained static site functionality.

### Website Structure

1. **Home**
2. **Requirements**
3. **Research**
4. **Algorithms**
5. **UI Design**
6. **System Design**
7. **Implementation**
8. **Testing**
9. **Evaluation**
10. **Appendices**
    * User manual and Deployment manual
    * GDPR and Privacy of Data
    * Development Blog (External Link)
    * Monthly Video

## 3. Detailed Page Requirements & Common Issues

### 3.1 Home Page

* **Contents:**
  * Project Title.
  * Abstract (3 paragraphs): Problem statement, Your solution, Achievement and impact.
  * 8-minute project introduction video showcasing functionalities.
  * Development Team: Photos, names, emails, and roles (Client Liaison, UI Design, Researcher, Programmer, Report Editor, Tester).
  * Project Management: Gantt chart (from Oct 20, 2025, to March 27, 2026).
* **Common Issues:** Abstract too brief; missing background/motivation; video missing or low resolution/poor audio; Gantt chart too small to read.

### 3.2 Requirements Page

* **Contents:**
  * Partner introduction and project goals.
  * Requirement gathering methods (surveys, data analysis).
  * Personas (typical users).
  * Use Cases (Diagram and list).
  * MoSCoW Requirement List (Functional and Non-functional tables).
* **Common Issues:** Missing use case diagrams; requirements described in only 2-3 words; use case diagrams formatted as workflow diagrams.

### 3.3 Research Page

* **Contents:**
  * Related Projects Review (at least 1 existing similar project).
  * Technology Review: Comparison of solutions, devices, algorithms, and languages/frameworks.
  * Summary of technical decisions.
  * References (IEEE style).
* **Common Issues:** Brief review section; abrupt transitions between topics; missing summary of technologies; lack of IEEE-style citations in the body text.

### 3.4 Algorithms (If applicable)

* **Contents:**
  * Models: Key ideas of chosen algorithms.
  * Data: Dataset details, preprocessing, and training/testing sets.
  * Experiments: Design, performance metrics (e.g., % accuracy), quantified results, and hyperparameter investigation.
  * Discussions: Failure cases and improvement suggestions.
* **Common Issues:** Unclear evaluation metrics; lack of quantitative evaluation; missing/poorly formatted references.

### 3.5 UI Design & System Design

* **UI Design:** Principles (simplicity, consistency, etc.), hand-drawn sketches, and URL to interactive high-fidelity wireframes (e.g., Figma).
* **System Design:**
  * System architecture diagram and component descriptions.
  * Site Map, Sequence Diagrams, Design Patterns, Class Diagrams (if applicable).
  * Data Storage: Data schema/ER diagram.
* **Common Issues:** Missing components in architecture diagrams; ER diagrams in incorrect formats or containing inaccuracies.

### 3.6 Implementation

* **Requirement:** Describe how key features were implemented.
* **Documentation:** Explain frameworks, plugins, or libraries used. Use subsections for specific features (e.g., authentication, database connection, PDF generation).
* **Visuals:** Use sequence diagrams and short code snippets to aid explanation.
* **Common Issues:** Images failing to load; core components missing from the architecture diagram.

### 3.7 Testing

* **Contents:** Testing strategy, Unit/Integration testing, Compatibility, Responsive design, Performance/Stress testing, and User Acceptance Testing (UAT).
* **UAT Details:** Simulated testers, test cases, and feedback from partners.
* **Common Issues:** Missing details on how tests were conducted; relying solely on manual integration testing (should be automated); missing project partner feedback.

### 3.8 Evaluation

* **Contents:**
  * Achievement table (MoSCoW functionalities vs. status).
  * List of known bugs.
  * Individual contribution distribution tables.
  * Critical evaluation (Stability, Efficiency, Maintainability, etc.).
  * Future work: Detailed discussion on potential enhancements.
* **Common Issues:** Incorrectly marking unimplemented requirements as "completed"; combining contribution tables (they must be separate for System and Website); brief "Future Work" section.

## 4. Appendices & Ongoing Deliverables

### 4.1 Development Blog

* **Frequency:** Updated **every two weeks** in Term 2.
* **Platform:** WordPress, UCL blogging tools, or preferred public blog.
* **Content:** Research, sketches, screenshots, algorithm snippets, and progress updates.

### 4.2 Monthly Video

* **Requirement:** 1-2 minute video update on findings and progress.
* **Deadline:** By the 15th of each month.
* **Submission:** OneDrive link (set to "Anyone with the link") submitted via Moodle/Project website.

### 4.3 Manuals & Legal

* **User Manual:** Guide for users with screenshots and test account credentials.
* **Deployment Manual:** Step-by-step guide for project partners to deploy the source code.
* **Legal:** Document GDPR, privacy of data, and source code licenses.

---

## 5. Marking Criteria

* **Home:** Quality of abstract, video, and Gantt chart.
* **Requirements:** Clarity of MoSCoW, personas, and use cases.
* **Research:** Depth of comparison and quality of references.
* **Implementation:** Depth of technical description for key features.
* **Testing:** Thoroughness of strategy and UAT.
* **Evaluation:** Concrete future plans and justified conclusions.
* **Clarity:** Spelling, grammar, and effective communication.
